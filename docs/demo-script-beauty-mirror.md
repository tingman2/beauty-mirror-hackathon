# 「妆镜」Demo 演示脚本 + 评委问答救命页

> 用途：现场演示照着走、评委追问照着答。**实话实说**比吹牛安全——这套东西的可信度就在"知道自己哪里不行"。
> 入口：http://127.0.0.1:8765/ （或双击 `products/beauty_mirror/启动妆镜Web.command`）

---

## 0. 一句话定位（开场就说这句）

> **「一张素颜照 + 3 道问卷，看懂你的皮肤现状，给出有依据的护肤/美妆方案，再按你的风格找到能跟练的妆教。」**

接着补一句**差异化**：

> 「和市面上"上传照片出个结论"不同，我们把**每个结论的来源都摆出来**——哪些来自问卷、哪些来自照片、哪里可能不准，都写在报告里。」

## 1. 三分钟演示脚本（标准版）

| 时间 | 操作 | 台词（要点） | 看什么 |
|---|---|---|---|
| 0:00 | 打开首页 | 「第一步，传一张素颜照，答 3 道题。」 | **运行状态卡**：视觉段是否就绪、内容来源、缓存条数 |
| 0:15 | 勾选隐私确认 → 传照 | 「照片只进本机临时目录，**不上传第三方、不用于训练**，会话结束即删。」 | 隐私确认门禁（不勾选传不了） |
| 0:30 | 答 3 题 → 生成报告 | 「肤色分类**不靠照片猜**，3 道题由规则确定性推导，零幻觉、可复现。」 | 后台视觉预热并行（不卡） |
| 0:50 | 报告页顶部 | 「这是结论：可见问题 + 肤质。注意——**肤质来自问卷，可见问题来自照片**。」 | **依据说明**（basis） |
| 1:05 | 可见问题列表 | 「每项都带**置信度**。」 | 置信度条 |
| 1:15 | **检测局限**卡片 | 「这里是我们**主动暴露的短板**：分辨率低会漏检、同一张图结果可能不一致，**未检出≠不存在**。」 | 局限说明（加分项） |
| 1:25 | **问卷依据**折叠 | 「报告和问卷**逐题对应**，你可以核对。」 | 3 题回显 |
| 1:35 | 合规自查 | 「发出去之前的文案，**用规则过一遍**医疗红线/绝对化用语，**不让模型自己批自己**。」 | 合规徽章 |
| 1:45 | 点「去看妆教跟练」→ 选风格 | 「选一个风格，我们有**平台编排的跟练脚本**。」 | 5 个风格标签 |
| 1:55 | **平台跟练脚本**块 | 「这是**平台编排的步骤**（标注了"非博主原文"）。」 | 2 个脚本 + 开始跟练 |
| 2:05 | **博主作品**块 | 「这是真实博主内容，**只做风格参考 + 跳转原平台**——因为没拿到转授权，我们**不转载博主正文**。」 | 卡片 + 「版权归原作者」 |
| 2:20 | 点「开始跟练」 | 「全屏跟练：**原博主妆教图 + 前置镜头**，逐步大字 + 计时。」 | 分步 + 计时 + 隐私声明 |
| 2:40 | （可选）生成带妆图 | 「也能 AI 生成一张"你的带妆效果"作**风格灵感**（非最终效果）。」 | 3 张候选 + 评分（不好看就跳过） |
| 2:55 | 收尾（跟练完成弹窗） | 「跟练完成会弹窗，扫码入群——社群是留存入口。」 | **跟练完成弹窗 + 社群二维码** |

**如果时间只够 60 秒**：只演 **报告页的"依据 + 局限"** 和 **跟练页的"脚本 / 博主内容"两块**——这两处最能体现"我们和别人不一样"。

## 2. 一页速查：已知限制与依据（评委追问救命页）

| 问题 | 我们的真实情况 | 怎么答 |
|---|---|---|
| **痘印/毛孔会漏检？** | 会。真人样本上 Qwen-VL **漏检痘印**，两个模型都判"无" | 「会。所以我们**主动注明"未检出≠不存在"**，并引导**拍两颊特写补测**；要量化就得走 50 张标注集，我们方案已就绪。」 |
| **准确率多少？** | **尚未达标**，未做标注集 | 「我们**没有声称准确率**——单张照片不能当准确率。评测方案（标准/样本/授权/隐私）已写完，缺的是志愿者照片。」 |
| **肤质怎么来的？** | **问卷规则**，不是照片 | 「肤质**不由照片推断**，3 道题 → 确定性规则，零成本零幻觉、可复现。」 |
| **妆效为什么一般？** | 生成式模型**重绘**，会掉眉/改脸/强度不可控 | 「AI 妆效是**辅助/风格灵感**，不是最终效果。真要做**实时试妆**得上专业美妆 SDK（YouCam/美图），我们评估过、报价也查了（≈¥0.7/次），**demo 阶段先不接**。」 |
| **数据从哪来？** | Apify 第三方抓取，**未获转授权** | 「内容来自第三方数据平台。**没转授权，所以我们不转载正文，只保留作者/跳转链**（方案 B）；Apify 账号目前是 FREE 预览额度，内容走本地缓存。」 |
| **隐私怎么保证？** | 临时目录 + 会话结束即删 + 日志脱敏 | 「照片只进**系统临时目录**，进程退出即删；**日志不记照片内容与密钥**；上传前有**隐私确认**且服务端二次校验。」 |
| **是不是套壳调 API？** | 是，但工程量大 | 「模型是调的（Qwen-VL / qwen-image-edit），**我们有完整 Harness**：预热并行、超时重试、多层降级、规则合规、内容代理、会话与隐私。**换模型不改业务代码。**」 |
| **现场断网怎么办？** | 有全离线兜底 | 「加 `--offline` 就是**全离线模式**，视觉与内容都走本地兜底，**现场绝不白屏**。」 |
| **商业模式？** | 未定 | 「先验证"看懂皮肤 + 能跟练"的留存；内容侧是**导流**逻辑（跳原平台），不自己囤内容。」 |

## 3. 预设 Q&A（按被问概率排序）

**Q1：这跟美颜相机/试妆 App 有什么区别？**
A：它们解决"好看"，我们解决"**看懂 + 怎么化**"。我们给的是**有依据的皮肤结论 + 可跟练的步骤**，妆效只是辅助。

**Q2：凭什么相信你的检测？**
A：不凭单张照片。我们**把置信度和局限都摆出来**，并规划了标注集评测；**不达标就不上线**。

**Q3：为什么不做实时试妆（摄像头叠妆）？**
A：做过，**取消了**——自研 AR 妆层对位/浓度调不到位（实测效果差）。真要做就接专业 SDK，**demo 阶段不值得**。

**Q4：博主内容会不会侵权？**
A：**没转授权就不展示正文**，只留作者名 + 跳转链；封面图已标"版权归原作者，仅风格参考"。**上线前必须拿到转授权或改成纯跳转。**

**Q5：一套跑下来多少钱？**
A：视觉检测约 **1–2 秒 / 几分钱**；生成带妆图是**可选彩蛋**，一次 3 张 + 评分，成本更高，现场可不用。

**Q6：为什么用问卷判断肤质？**
A：**照片判肤质在会议室光线下必翻车**（我们实测过）。问卷规则**确定性、可复现、零成本**。

**Q7：能扩到男用户/其他人群吗？**
A：逻辑通用，**要换的是风格标签与文案**（`data/style_tags.yaml`），代码不动。

**Q8：下一步做什么？**
A：① 10–20 张真实照片做小规模验证；② 拿转授权；③ 补用户档案与指标（跟练完成率 / D7 复访 / 入群率）。

## 4. 现场风险预案

| 风险 | 预案 |
|---|---|
| 网络不稳 / 模型超时 | **启动时加 `--offline`**：视觉与内容走本地兜底，不白屏（页内会**明确标注是示例**） |
| 摄像头不可用 | 跟练页**自动退化为纯步骤**，不影响流程 |
| 照片被模型判"非真实照片" | 属正常行为，页面提示**重拍**；可换一张 |
| 生成带妆图太慢/不好看 | **跳过这个彩蛋**，不影响主链路 |
| 评委问"准确率" | 见 §2，**别编**，讲评测方案 |

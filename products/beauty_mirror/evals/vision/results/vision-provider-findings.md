# 视觉段评测：真实 API 试跑结论

> 日期：2026-10-05
> 样本：7 张 Wikimedia Commons 开放许可人像（**已过滤为彩色明亮**，平均亮度 96–166）
> 环境：`VISION_MIN_CONFIDENCE=0.35`，超时 30s，`sdk_max_retries=0`

> ⚠️ 这 7 张**不是**标注评测集：无 ground truth、非素颜、不含真实皮肤问题。
> 本文只判断"模型能不能干这活"与"耗时能不能接受"，**不构成准确率结论**。

---

## 候选 1：GLM-4V（智谱）—— ❌ 不可用

两种失败模式，都不是提示词问题：

| 模式 | 表现 |
|---|---|
| A. 用"图片太暗"回避 | 7 张**明亮**彩色照里 3–5 张被判 `image_quality.ok=false` |
| B. 被逗后编造 | 提示词改为"必须逐项判断"后，**7 张不同照片返回一字不差的同一答案** `acne_marks 0.7 左脸颊` |

另：一张真实人像触发智谱内容审核（`code 1301`）。

**结论：不得使用 GLM-4V。也不要采用"模式 B"那版提示词——它只会掩盖问题。**

## 候选 2：豆包 `doubao-seed-evolving`（火山方舟）—— ⚠️ 能用但太慢

### 权限排障过程（值得记下来）

| 步骤 | 结果 |
|---|---|
| 旧 key（首个提交的） | 认证通过，但所有模型 404 |
| 列出 `/models` | 135 个模型，含 `status` / `modalities` / `task_type` 字段 |
| 按 `task_type=VisualQuestionAnswering` 筛出 30 个，全部实测 | **29 个 404**，仅 **`doubao-seed-evolving` 返回 200** |
| 旧 key 调该模型 | ❌ HTTP 403 `you do not have access to the requested resource` |
| **新 key**（后提交的）调该模型 | ✅ 200 |

**教训**：`/models` 是平台**全量目录**，不代表账号有权限；报错 `does not exist **or you do not have access to it**` 要按"没权限"处理，不是"模型名写错"。

### 行为质量：✅ 真的在读图

| 图片 | 检出 |
|---|---|
| c05 | `redness 0.96 moderate [左脸颊,右脸颊]`、`t_zone_oil ...` |
| c06 | `redness 0.96 moderate [双侧面颊]`、`t_zone_oil 0.82 ...` |
| c01 / c03 / c07 / c08 | 空检出（无可见问题） |

**关键**：不同照片给出**不同的置信度与部位**，没有出现 GLM 那种"复读机"行为。

### 延迟：❌ 超标

| 指标 | 修 SDK 重试前 | 修 SDK 重试后 |
|---|---|---|
| 耗时范围 | 6.5s – **91s** | 8.4s – **22.8s** |
| 均值 | 33s | 16.8s |
| 中位 | 25s | **18.1s** |
| 超时次数 | 1/7 | 0/4 |

PRD 定的目标是 **P95 ≤ 15s** → 中位数就已经 18s，**直接超标**。

### 附带修掉的一个真 bug

`OpenAI(timeout=30)` 只约束**单次**请求，而 SDK 默认 `max_retries=2`，
所以最坏情况实际放到了 **91s**（30×3）。已改为 `max_retries=0`，超时硬生效。

## 结论与建议

| 候选 | 行为 | 延迟 | 结论 |

| GLM-4V | ❌ 拒答或编造 | — | 淘汰 |

### 两个可落地的方案

1. **异步化（推荐，零成本）**：把视觉调用与「3 道肤质问卷」**并行**跑。
   用户答问卷本身要 5–8 秒，视觉的 ~18s 大部分被掩盖。这是最划算的修法。
2. **换 Qwen-VL**：把延迟压到秒级。代码里 `qwen_vl` 已挂好，只差一个 DashScope key。

> 注意：`doubao-seed-evolving` 名字里带 "evolving"，属于会滚动的别名，
> 延迟与行为可能不稳定，**不适合作为生产主选**，更适合当兜底候选。

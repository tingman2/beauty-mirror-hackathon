> 本文只定义怎么评，不放任何真人照片；照片由志愿者/授权数据集提供，**我们不自行收集**。

---

## 0. 为什么必须单独做评测

现有 `evals/vision/run_eval.py` 只跑**离线 smoke test**（mock provider + 召回闸门），验证"评测框架能跑通"；
它**不构成准确率结论**。要判断 Qwen-VL 到底能不能用，必须有带 ground truth 的真人素颜照评测集。

---

## 1. 评测对象与范围

| 评 | 不评 |
|---|---|
| **可见问题检测**（闭集 5 类：痘印 / 泛红 / T 区油光 / 毛孔 / 黑眼圈），逐类 + 逐图 | **肤质分类**（干/油/混/敏）——肤质只由 3 道问卷的**确定性规则**得出，不由照片判断，不纳入准确率 |
| 画质/重拍判定（`image_quality.ok` 与 `needs_retake`） | 护肤/美妆方案的医学正确性（非医疗器械，方案是通用建议） |
| 报告一致性（见 §3.3）与合规（见 §3.4） | 生成文案的"好看程度"（主观） |

---

## 2. 样本要求

| 项 | 要求 |
|---|---|
| 数量 | **50 张起步**（每类正例 ≥ 10 张，另含 ≥ 10 张"无可见问题"负样本） |
| 场景 | 自然光为主，覆盖：正脸 / 微侧、冷白皮 / 暖黄皮 / 深肤色、戴/不戴眼镜、干/油/敏自评各若干 |
| 排除 | 强滤镜、重度美颜、逆光/过暗、人脸过小、卡通/合成图 |
| 画质分层 | 明确区分"可判定"与"应重拍"两组，重拍判定单独统计 |
| 格式 | JPEG/PNG，长边 ≤ 2000px；上传前**去除 EXIF**（含 GPS、设备、时间） |

---

## 3. 评测标准

### 3.1 主指标（可见问题检测）

- 逐类计算 **Precision / Recall / F1**（以图片为样本单位：该图是否检出该类）。
- **主指标 = 5 类宏平均召回（macro Recall）≥ 0.80**（沿用 PRD 闸门）。
- 允许"检出但部位/严重度不同"记为**命中**（部位信息单独评估，不卡主指标）。
- 置信度不作准确率指标，但记录 `≥0.35` 阈值下漏检/误检分布，用于调 `VISION_MIN_CONFIDENCE`。

### 3.2 画质/重拍判定

- `needs_retake` 的 **精确率**（被判重拍的图里，人工也认为不可判定的比例）与**召回率**。
- 目标：重拍误伤率 ≤ 20%（避免把好照片赶走）。

### 3.3 报告一致性（规则可自动查，人工抽检）

| 检查 | 通过标准 |
|---|---|
| 报告头部"可见问题 N 项" == 列表条数 == 针对性护理条数 | 必须一致（已有单测锁定） |
| 肤质结论 == 3 道问卷规则输出 | 必须一致（确定性） |
| 护肤建议与肤质族匹配；针对性护理与检出的可见问题一一对应 | 人工判定一致 |
| 问卷答案逐题回显 == 用户所答 | 必须一致（`answers_display`） |
| 不确定表述 | 照片相关结论必须带"估计/存在误差/以置信度为准"；不得出现无依据的确定性医学结论 |

### 3.4 合规（自动，必过）

- 全部生成文案过 `tools.compliance_check`，`status` 必须为 `pass`（医疗红线 / 绝对化用语 / 效果承诺）。
- 目标：**100% 通过**（这是硬闸，不是统计指标）。

---

## 4. 标注流程

1. **两名标注者独立标注**同一批图（闭集 5 类 + 是否可判定 + 部位）。
2. 分歧用 **Cohen's κ** 衡量一致性；κ < 0.60 的类别先开会对齐标注口径，再重标。
3. 分歧样本由**第三人仲裁**，形成最终 ground truth。
4. 标注与模型输出**分开存放**，评测脚本只读最终共识，避免"边看模型结果边改标注"。

---

## 5. 照片授权与隐私处理（硬约束）

### 5.1 授权

- **只用两类来源**：① 志愿者**书面/电子知情同意**的照片；② 明确授权用于研究/评测的开源人像数据（许可证允许）。
- 知情同意书要点：用途（模型评测）、处理方式、保存期限、**可随时撤回并要求删除**、是否匿名化展示、联系方式。
- **禁止**：自行爬取/收集真人照片；使用社交媒体抓取的私人照片；使用未获授权的明星/公众人物照片。

### 5.2 隐私处理

| 环节 | 做法 |
|---|---|
| 上传 | 走页面/本地通道，照片**只进本机临时目录**，不进仓库、不进测试资料、不进日志 |
| 去标识 | 上传前去除 EXIF；文件名替换为随机 ID（如 `sub-007-01.jpg`），与身份映射表分离保存 |
| 存储 | 仅存于评测专用目录，**不入版本库**（`.gitignore` 排除）；映射表加密/单独保管 |
| 访问 | 仅评测执行者可见；不用于训练、不用于展示、不对外分享 |
| 删除 | 评测结束（或志愿者撤回）后 **30 天内删除**原图与派生产物，保留删除记录 |
| 日志 | 服务端日志只记路由/状态/耗时，**不记照片内容与 base64**（已实现并有测试） |

### 5.3 撤回机制

- 每个志愿者一个匿名 ID，撤回时按 ID 删除其全部照片与标注。
- 若已有评测结论已发布，注明"某 ID 样本已撤回"，必要时重跑。

## 6. 执行与产出

```sh
# 1) 准备评测集（本地，不入库）：evals/vision/fixtures/<匿名ID>.jpg + .json(ground truth)
# 2) 跑评测（真实 provider）
cd products && python -m beauty_mirror.evals.vision.run_eval --providers qwen_vl --manifest evals/vision/manifest.local.jsonl
# 3) 报告落盘
#    evals/vision/results/<date>-qwen_vl.md：逐类 P/R/F1、宏平均、重拍误伤率、失败样本清单
```

产出：
- `results/<date>-<provider>.md`：指标 + 混淆矩阵 + 失败样本（匿名 ID）+ 结论（达标 / 不达标 / 需换模型）
- 达标线：**宏平均召回 ≥ 0.80 且合规 100%**；否则不上线，或换 provider / 收紧提示词后重测。

---

## 7. 局限与风险

- 50 张只够**初步判断**，置信区间宽；要下有统计意义的结论需数百张。
- 手机前置/后置、光线差异会显著影响结果，评测集需覆盖但难以穷举。
- 深肤色在小样本下容易被低估，需**分层报告**，不看单一总体均值。
- 单张照片（如本次初步检查）**永远不能**作为准确率证据，只能发现明显误判/矛盾。
